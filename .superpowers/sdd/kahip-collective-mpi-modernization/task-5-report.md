## Projection protocol TDD evidence

The two-rank regression owns two fine and two coarse nodes per rank. Every fine
node projects to the other rank, and fine-node order intentionally disagrees
with coarse-node/reply order. Expected fine labels are `{203,202}` on rank 0
and `{101,100}` on rank 1.

The test interposes MPI through PMPI and counts the protocol calls only while
`parallel_project` executes. RED preserved correct labels but observed:

```text
MPI_Alltoallv=1 MPI_Isend=2 MPI_Probe=2
```

This proved at runtime that the existing collective result was ignored while
the old point-to-point request/reply protocol supplied the behavior.

The implementation now performs exactly two dense `mpi::all_to_all_v`
exchanges using wire records:

- request: stable fine-global request ID plus coarse-global node ID
- reply: stable request ID, coarse-global node ID, and label

Requests are stable-sorted by coarse-global ID/request ID within destination;
replies are stable-sorted by request ID/coarse-global ID within requester.
Replies are correlated by the explicit request ID and checked against the
coarse-global ID, never by arrival position. Both segmented send buffers own
their storage through their blocking collective calls. The superseded
projection `m_messages`, `MPI_Isend`, `MPI_Probe`, and `MPI_Recv` code was
removed. GREEN preserved the exact labels and observed:

```text
MPI_Alltoallv=2 MPI_Isend=0 MPI_Probe=0
```

## Canonical MPI trace facility

`KAHIP_ENABLE_MPI_TRACE` is a target-scoped CMake option and defaults to OFF.
When OFF, the trace macro does not evaluate its argument, runtime storage is
absent, and file output is a no-op. A release run with
`KAHIP_MPI_TRACE_PATH` set wrote no trace files and retained the exact upstream
partition hash.

The readable `kahip-mpi-trace-v1` schema records:

1. graph-distribution nodes and edges
2. contraction label-to-coarse mapping
3. quotient node weights and edges
4. projection requests and replies
5. ghost label updates
6. block propagation
7. final global partition order

Canonicalization copies and sorts records by stage and then global ID,
semantic key, and payload. The exact fixture reverses insertion order and
requires identical bytes. The projection MPI fixture checks exact request and
reply text on each rank. A real two-rank block-down fixture executes the
vcycle-only hook, propagates remote block assignments, and checks exact
canonical block records.

Trace TDD evidence:

- schema/canonical test RED: trace header absent
- full smoke RED: rank trace not written before app/hook integration
- GREEN: exact canonical fixture, exact projection fixture, exact block hook,
  and the trace-enabled integration smoke all pass

The fixed `ultrafastmesh` executable is built with
`PARALLEL_LABEL_COMPRESSION`, whose CLI table omits `--num_vcycles`; its normal
one-cycle tuple therefore does not execute the vcycle-only block path. The
focused block test covers the Task 5 hook/schema. Broad algorithmic parity of
that legacy transport remains for the later block/ghost migration tasks.

## Fix round 2: ghost exchange identity and collective run IDs

This round is based on Task 5 fix-round-1 commit

### Real ghost reset-path RED/GREEN

The new two-rank regression constructs one owned node and one cross-rank edge
per rank, then runs the real `parallel_label_compress` loop for four label
iterations. Before the fix, `update_ghost_node_data_finish()` reset
`m_recv_iteration` every outer iteration, so the globally canonical trace
contained the same record twice. Rank 0's exact duplicate was:

```text
ghost-update cycle=5 level=2 epoch=coarsening round=1 global=1 owner=1 requester=- receiver=0 key=label label=1
```

Rank 1 had the symmetric duplicate for global node 0. The focused RED failed
because neither `iteration=1` nor `iteration=3` existed (18 of 19 assertions
passed on each rank). The v3 schema adds `iteration` before the existing
exchange-local `round`; the real outer loop sets it from its deterministic
label-iteration index. `KAHIP_MPI_TRACE_SET_HIERARCHY` resets it to zero when
the semantic stage changes, while the compile-time-OFF iteration macro does
not evaluate its argument. The focused GREEN contains otherwise-identical
ghost updates at `iteration=1 round=1` and `iteration=3 round=1`. The trace
schema/canonical, real projection/ghost, and vcycle block-hook focused set
passed 5 of 5.

### Collective, collision-resistant trace run ID RED/GREEN

The filename regression first demonstrated the sanitizer collision exactly:
both `job/42` and `job?42` produced
`trace/output.run-job_42.rank3.trace`. The MPI regression initially failed to
compile because `resolve_run_id_collectively` did not exist. GREEN resolves
one run ID per communicator:

- a root ID is broadcast and every rank contributes to a mismatch
  `MPI_Allreduce`; all ranks throw if any local explicit or scheduler-derived
  ID differs;
- with no ID, only rank 0 creates a non-security nonce from `random_device`
  plus system and steady clock state, then broadcasts it;
- explicit IDs remain deterministic; filenames include a fixed 64-bit FNV-1a
  hexadecimal suffix of the original unsanitized ID, so sanitizer collisions
  do not alias.

The focused CTest command selected the collision unit test and the two-rank
MPI executable. Both tests passed. The MPI executable verifies the rank-zero
versus rank-one mismatch fails on every rank, independently re-broadcasts and
compares the no-ID fallback, and verifies exact `oracle-fixture` agreement.
No lifecycle failure or deadlock occurred. All resolver and nonce operations
are inside `#if KAHIP_ENABLE_MPI_TRACE`; the default-OFF build introduces no
run-ID MPI work. The integration smoke first went RED looking for the old
`.run-smoke.rank0.trace`; GREEN discovers the stable-hash filename, requires
exactly one file per rank, and verifies both ranks share the same run stem.
